# handphon-game — v2

방치형 게임의 **프로덕션 재작성** 브랜치. 개발자용 문서다.

게임 자체에 대한 설명(플레이 방법·밸런스 의도·매크로 방지 설계·진행 속도표)은
**`main` 브랜치의 README** 에 있다. 이 브랜치는 복사본을 들고 있지 않는다 — 금방 어긋난다.

## main 과의 관계

| | main | v2 (여기) |
|---|---|---|
| 역할 | 프로토타입 · 기획 검증 | 프로덕션 구현 |
| 상태 | 동작함. 지인 테스트 중 | 스캐폴딩만 |
| 배포 | 정적 호스팅 (서버 없음) | 미배포 |
| 코드 | 버릴 것 | 남길 것 |

기획 이터레이션은 **main 에서** 한다. 지인이 플레이할 수 있는 빌드가 그것뿐이다.
main 에서 조정한 **밸런스 수치는 `packages/config` 로 그대로 이전**되므로 버려지지 않는다.
다만 신기능을 main 에 정성껏 구현하는 건 낭비다 — 검증에 필요한 최소 구현만.

옛 코드를 참고할 땐 체크아웃하지 말고: `git show main:assets/js/game.js`

## 구조

```
packages/
  config/   밸런스 데이터. 값만, 로직 없음
  sim/      시뮬레이션 코어. 순수 함수
              ↑ 클라와 서버가 같이 쓴다 ← 이 구조의 핵심
apps/
  api/      게임 API. 서버에 올라가는 유일한 앱
  client/   게임 화면. 웹 정적 호스팅 + Capacitor 번들 양쪽에 쓰임
  mobile/   Capacitor 껍데기. client 빌드를 앱에 번들
```

각 앱의 상세는 해당 폴더의 README 참고.
[apps/api](apps/api/README.md) · [apps/client](apps/client/README.md) · [apps/mobile](apps/mobile/README.md)

## 설계 원칙 (비타협)

구 코드가 이걸 위반해서 재작성하게 됐다. 다시 어기면 또 엎는다.

1. **시뮬레이션 코어는 순수 함수** — 모듈 전역 상태 금지.
   구 `game.js` 는 `S()` 로 전역 세이브 하나를 물고, 캐시·콤보·매크로 감시가 모듈 전역이라
   서버에서 동시 사용자를 처리할 수 없었다.
2. **시간과 난수는 인자로** — 코어 안에서 `Date.now()` / `Math.random()` 을 부르지 않는다.
   구 코드는 출석 보상이 기기 로컬 시간 기준이라 시계만 바꾸면 무한 수령이 됐다.
   시드를 state 에 넣으면 세이브 코드만으로 버그를 그대로 재현할 수 있다.
3. **서버가 권위** — 클라는 액션만 보낸다. `{money: 5000}` 이 아니라 `{buy: 'g3'}`.
4. **지연 계산** — 전 유저를 크론으로 틱하지 않는다. 요청 시 `now - lastTickAt` 만큼 한 번에.
5. **탭은 배치 전송** — 탭마다 요청하면 유저당 14 rps, 5초 배치면 0.2 rps. 70배 차이.
6. **밸런스는 코드 밖** — 도전과제도 클로저가 아니라 선언적 조건으로.
   서버가 config 를 내려줘야 클라 재배포 없이 수치를 고칠 수 있다.

## 진행 상태

| 대상 | 상태 | 막고 있는 것 |
|---|---|---|
| 워크스페이스 스캐폴딩 | ✅ 완료 | — |
| `packages/config` | 스텁 | 기획 확정 |
| `packages/sim` | 스텁 | 기획 확정 |
| `apps/api` 1~4 (인프라·계정·관측·결제원장) | 미착수 | **없음. 지금 가능** |
| `apps/api` 5~6 (게임 액션·랭킹) | 미착수 | 기획 확정 |
| `apps/client` | 스텁 | UI 프레임워크 결정 |
| `apps/mobile` | 미착수 | client 선행 |

### sim/config 재개 시점

- 지인 피드백에서 같은 얘기만 반복되고 새 지적이 안 나올 때
- 기능 목록이 2~3주 안 바뀔 때
- "이제 밸런스 숫자만 만지면 되겠다" 싶을 때

그때 **확정된 기능 목록을 액션 목록으로 옮기는 것**부터 시작한다.

## 미결 결정

| 결정 | 영향 범위 | 비고 |
|---|---|---|
| 숫자 타입 — 일반 `number` vs `break_infinity.js` | `sim/economy.ts` | 나중에 바꾸면 산술이 전부 뒤집힘 |
| UI 프레임워크 | `apps/client` 전체 | 방치형은 `money` 가 초당 60회 바뀜 |
| 웹 우선 vs 앱스토어 우선 | 결제 스택 | PG 3% vs 스토어 IAP 30% |

## 달력이 걸린 것들

코드와 무관하지만 출시를 막는다. 리드타임이 길어 미리 알아봐야 한다.

- 사업자 등록 → PG 계약(포트원·토스페이먼츠)의 전제
- 애플 개발자 계정 — 법인은 D-U-N-S 번호 때문에 몇 주 걸리기도
- 구글 플레이 개발자 계정 — 신규 개인 계정은 테스터 20명 × 14일 클로즈드 테스트 요건이 있다
  (현재 정책 확인 필요. 사실이면 **지인 테스트를 클로즈드 트랙으로 돌려 일석이조**)
- 게임물 등급분류 — 웹으로 직접 서비스하면 GRAC 직접 신청, 스토어 경유면 자체등급분류
- 확률형 아이템 확률 공개 의무 — 코인으로 뽑기를 넣을 경우

```bash
npm install
npm run typecheck
npm test
```

- 내부 패키지는 빌드 없이 **TS 소스를 그대로 export** 한다 (`exports: "./src/index.ts"`).
  개발 중 빌드 단계가 안 끼어든다.
- 패키지 매니저는 npm workspaces. pnpm 으로 옮기려면 락파일만 갈아끼우면 된다.
