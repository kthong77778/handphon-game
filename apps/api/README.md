# @handphon/api

게임 API 서버. **서버에 배포되는 유일한 앱**이다.
클라이언트 코드는 앱 번들/정적 호스팅으로 가고, 여기엔 API 와 데이터만 있다.

## 상태

미착수. 아래 순서로 진행한다.

| 순서 | 내용 | 기획 의존 |
|---|---|---|
| 1 | 인프라 관통 — Postgres + Redis + 서버를 실제 배포까지 한 번 | 없음 |
| 2 | 계정 — 회원가입·로그인·세션·소셜 | 없음 |
| 3 | 관측 — 로깅·에러 추적 | 없음 |
| 4 | 결제 원장 — 샌드박스 결제 → 영수증 검증 → 원장 기록 | 상품 구성만 |
| 5 | 게임 액션 API | **기획 확정 필요** |
| 6 | 랭킹 (Redis ZSET) | 순위 기준 확정 필요 |

1~4 는 기획과 무관하므로 지금 진행 가능. 5 는 `packages/sim` 의 액션 목록이 정해져야 한다.

## 설계 원칙

- **서버가 권위.** 클라는 액션만 보낸다. `{money: 5000}` 이 아니라 `{buy: 'g3'}`
- **지연 계산.** 전 유저를 크론으로 틱하지 않는다. 요청이 올 때 `now - lastTickAt` 만큼 한 번에 계산
- **탭은 배치.** 탭마다 요청하면 유저당 14 rps, 5초 배치면 0.2 rps (70배 차이)
- **Redis 가 핫 스토어**, Postgres 는 내구성 원장. 단 결제만은 Postgres 직행 (ACID)

## 폴더

```
src/
  routes/    HTTP 엔드포인트
  auth/      인증·세션
  db/        스키마·마이그레이션·쿼리
  payment/   결제·영수증 검증·원장
  ranking/   랭킹 (Redis ZSET)
```
