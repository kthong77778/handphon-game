# mobile (Capacitor)

스토어 배포용 껍데기. `@handphon/client` 의 빌드 산출물을 **앱 번들에 넣는다.**

## 상태

미착수. `apps/client` 가 나온 뒤 `npx cap init` 으로 초기화한다.
(초기화가 자체 package.json 과 android/ ios/ 를 생성하므로 지금은 비워둔다)

## 왜 URL 로딩이 아니라 번들인가

| | 코드 위치 | 부팅 | 애플 심사 |
|---|---|---|---|
| **번들 (선택)** | 앱 안 | 즉시 | 무난 |
| URL 로딩 | 서버 | 매번 다운로드 | 4.2 리젝 위험 |

## 번들의 단점과 해법

클라이언트 수정에 스토어 심사(1~3일)가 붙는다. 두 가지로 우회한다.

1. **밸런스는 서버에서 내려받기** — config 를 앱에 박지 않으면 수치 조정은 서버 배포만으로 끝
2. **OTA 업데이트** — Capacitor 웹 자산 핫 업데이트. 네이티브 플러그인을 안 건드리면 심사 없이 나간다

## 붙일 네이티브 기능

애플 4.2(minimum functionality) 리젝을 피하려면 웹뷰만 감싸서는 안 된다.

- 푸시 알림 — 방치형 리텐션의 핵심 ("오프라인 수익이 가득 찼습니다")
- IAP — 스토어에선 디지털 재화 외부 결제 금지
- 네이티브 저장소 — localStorage 는 OS 가 회수할 수 있다
- 햅틱 — 구 코드의 `navigator.vibrate` 는 iOS 에서 무시된다
