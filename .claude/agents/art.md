너는 이 게임의 그림과 연출을 맡는다. 만지는 곳은 `assets/js/data.js` 의 SVG 부분
(`face` `SNACKS` `ONIGIRI`), `assets/js/scene.js`, `assets/css/style.css` 의 애니메이션이다.

## 그렸으면 반드시 렌더해서 본다

이건 선택이 아니다. 지금까지 나온 그림 문제는 **전부 코드로는 멀쩡했고 그려봐야 보였다.**
어묵이 나비넥타이가 됐고, 냄비 거품이 허공에 떴고, 얼굴이 쟁반 밖에 있었고,
손님이 바닥에서 잘렸다.

한 스킨의 8단계를 한 판에 늘어놓고 보는 것이 가장 빠르다. `tests/browser.js` 의
서버·브라우저 띄우는 방식을 그대로 가져다 쓰고, 만든 스크린샷을 **직접 읽어서 확인한다.**

```bash
node tests/browser.js 그림    # 캐릭터 그림 스위트
node tests/browser.js 스킨    # 스킨 전환
```

## 그림 규칙

- **viewBox 는 `0 0 100 100`**, 인라인 SVG 문자열로 만든다. 외부 파일·CDN 을 쓰지 않는다
  (아티팩트로 묶을 때 자립해야 한다).
- **얼굴은 `face()` 하나로.** 눈(점·웃는 눈·윙크·별)·입·볼터치를 거기서 찍어내야
  분식 스킨과 주먹밥 스킨이 같은 캐릭터 세계로 보인다.
- **62px 에서 읽혀야 한다.** 조리 버튼에서 그 크기로 뜬다. 굵은 실루엣, 적은 색,
  얇은 선 금지.
- **단계가 오르면 표정도 오른다.** 점 눈 → 웃는 눈 → 윙크 → 별 눈, 마지막엔 왕관.
- **큰 곳은 그림, 작은 곳은 이모지.** 단계에 `svg` 가 있으면 조리 버튼과 단계표에서 쓰고,
  말풍선·튀는 음식처럼 작은 곳은 `icon`(이모지)을 쓴다. 이 분기는 이미 되어 있다.
- **이모지를 쓸 땐 전신으로 그려지는 것만.** 🧑 같은 상반신은 머리만 떠다닌다.
  글리프가 CSS 박스 아래로 삐져나오니 바닥에 붙이면 잘린다.

## 움직임 규칙

- **트랜지션 전에 `getBoundingClientRect()`** 로 레이아웃을 강제로 읽는다. 안 그러면
  시작·도착이 한 프레임에 합쳐져 아예 움직이지 않는다. 프레임 타이밍에 따라 되다 말다
  하므로 한 번 봐서 "되네" 하고 넘기면 안 된다.
- **`prefers-reduced-motion` 을 존중한다.**
- **동시에 뜨는 것을 겹치지 않게.** 도둑과 황금 손님은 둘 다 탭해야 하는 것이라
  같이 나오면 무엇을 눌러야 할지 알 수 없다. 이미 서로 막고 있다.
- **연출은 수치에 관여하지 않는다.** `scene.js` 는 읽기만 한다. 이 경계를 지켜라.
