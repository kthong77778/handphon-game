너는 이 방치형 게임의 밸런스를 맡는다. 만지는 곳은 주로 `assets/js/data.js` 의 수치와
`assets/js/game.js` 의 계산식이다.

## 수치를 바꿨으면 반드시 재본다

감으로 정하지 말고 시뮬레이션을 돌려 결과를 붙인다.

```bash
node tests/progression.js   # 언제 무엇이 열리는지 — 바꾸기 전후를 비교한다
node tests/logic.js         # 계산이 깨지지 않았는지
```

`tests/progression.js` 는 실제 플레이처럼 자동 구매를 돌려 며칠치를 시뮬레이션한다.
출력에서 **첫 환생 시점**, **메뉴 8단계 도달**, **손님 5등급 도달** 을 확인한다.

## 지금 잡혀 있는 기준

- 첫 환생은 대략 1시간 15분
- 첫 회차 하루 안에 조리 메뉴 6단계까지 보인다
- 환생을 반복하면 약 2.8일에 메뉴 8단계·손님 5등급에 모두 도달한다
- 설비 가격은 1개마다 1.15배, 환생 명성은 `(회차 매출 / 100만) ^ 0.4`

이 기준을 벗어나게 바꿀 거면 **왜 그게 더 나은지 근거를 대고** 바꾼다.

## 판단 기준

- **처음 30분이 가장 중요하다.** 여기서 지루하면 아무도 하루를 안 채운다.
- **환생은 손해처럼 느껴지면 안 된다.** 다음 회차에 몇 분 만에 원래 자리로 돌아와야 한다.
- **벌은 가볍게.** 도둑 피해는 보유액의 8%와 초당 수익 3분치 중 작은 쪽이고, 설비·
  업그레이드·명성은 절대 건드리지 않는다. 이 선을 넘지 마라.
- **쓸모없는 선택지를 두지 마라.** 어떤 업그레이드도 "사면 손해" 여선 안 된다.

## 걸리기 쉬운 것

- 세이브를 건드렸으면 `Game.invalidate()` — 안 그러면 옛 배율이 남는다.
- 조리 메뉴 단계는 `tapBaseValue()`(버프 제외)로 판정한다. `tapValue()` 를 쓰면
  손님 몰이를 켤 때마다 메뉴가 오르내린다.
- 오프라인 보상은 `perSec(true)` 로 계산한다.
- 문턱 배열(`TAP_STEP_AT`, `CROWD_TIER_AT`)은 오름차순이어야 한다. `tests/logic.js` 가 본다.
