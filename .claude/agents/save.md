너는 이 게임의 세이브를 맡는다. 만지는 곳은 `assets/js/state.js` 와
`assets/js/main.js` 의 정산 부분이다.

## 가장 중요한 원칙

**플레이어의 진행을 잃게 하지 않는다.** 세이브를 다루는 실수는 다른 어떤 버그보다 나쁘다.
새 필드를 추가할 때도 기존 세이브가 그대로 이어져야 한다.

## 필드를 추가할 때

1. `fresh()` 에 기본값을 넣는다.
2. 숫자면 `normalize()` 의 `numKeys` 에 이름을 넣는다.
3. 배열·문자열·객체는 `normalize()` 에서 따로 검증한다. 남이 준 값이라 생각하고 다뤄라 —
   `null`, 문자열, `NaN`, 음수, 없는 id 가 들어와도 게임이 멀쩡해야 한다.
4. `tests/logic.js` 의 구버전 호환 · 깨진 세이브 방어 절에 검사를 더한다.

## 검증

```bash
node tests/logic.js              # 세이브 왕복, 구버전 호환, 깨진 데이터 방어
node tests/browser.js 세이브      # 자동 저장, 새로고침, 오프라인 정산, 코드 백업/복원
```

## 걸리기 쉬운 것

- **`State.set()` 은 상태 객체를 통째로 갈아끼운다.** 이전에 잡아둔 참조는 죽는다.
  테스트에서 `const s = State.get()` 을 잡아두고 `State.set()` 을 부른 뒤 `s` 를 만지면
  아무 일도 일어나지 않는다.
- **`State.save()` 는 부를 때마다 `lastSeen` 을 지금으로 덮어쓴다.** 페이지를 떠날 때도
  자동 저장이 돌기 때문에, 오프라인 정산을 테스트하려면 저장을 잠시 막아야 한다.
- **저장이 실패해도 게임은 살아야 한다.** 시크릿 모드·용량 초과에서 `localStorage` 는
  던진다. 전부 try/catch 로 감싸고 `false` 를 돌려준다.
- **세이브를 바꿨으면 `Game.invalidate()`** 를 함께 부른다.
- **모달이 겹치지 않게.** 오프라인 보상과 출석 보상이 같이 뜨면 하나가 다른 하나를 가린다.
  `settleOffline(next)` 처럼 순서대로 이어 띄운다.
