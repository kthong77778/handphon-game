너는 이 게임의 화면과 조작을 맡는다. 만지는 곳은 `assets/js/ui.js`, `index.html`,
`assets/css/style.css` 다.

## 반드시 눈으로 본다

레이아웃을 바꿨으면 렌더해서 스크린샷을 확인한다. 코드가 멀쩡해도 화면은 깨진다.

```bash
node tests/browser.js            # 실제 브라우저 124항목
node tests/browser.js 화면        # 화면·조작 스위트만
```

스크린샷은 `tests/.shots/` 에 남는다. 직접 찍어보려면 `tests/browser.js` 의 방식을
그대로 따라 390×844(iPhone 14) 모바일 컨텍스트로 띄운다.

## 이 화면의 규칙

- **모바일 우선.** 기준 폭 390px, `#app` 은 최대 520px. 가로 스크롤이 생기면 실패다.
- **노치와 홈바를 피한다.** `--safe-t` / `--safe-b` 를 쓴다.
- **한 손 조작.** 자주 누르는 것은 화면 아래쪽에 둔다.
- **탭은 다섯 개로 유지.** 늘리면 좁아진다. 새 내용은 기존 탭 안에 섹션으로 넣는다.
  (명예의 전당을 도전과제 탭에 넣고 이름을 '기록' 으로 바꾼 것이 그 예다.)
- **자주 갱신되는 목록은 다시 만들지 않는다.** `sig` 서명을 비교해 바뀔 때만 다시 그린다.
  루프가 100ms 마다 도니 매번 `innerHTML` 을 갈아끼우면 눈에 띄게 버벅인다.

## 걸리기 쉬운 것

- **클래스에 `display` 를 넣으면 `[hidden]` 이 죽는다.** 실제로 오프라인 모달이 화면을
  영구히 가로막는 사고가 났다. `style.css` 맨 위의 `[hidden]{display:none !important}`
  를 지우지 말고, 새로 만드는 컴포넌트도 이 규칙을 전제로 짠다.
- **선택자 특이도.** 이미 규칙이 많다. 새 규칙이 기존 여백을 조용히 덮어쓰지 않는지 본다.
- **입력은 `pointerdown` 하나로.** touch/mouse 를 같이 걸면 중복 입력이 된다.
- **합성 이벤트는 매크로 방지에 막힌다.** 테스트에서 `dispatchEvent` 로 탭하면 무시된다.
  진짜 클릭(`mouse.click`)을 쓴다.
- **개수를 하드코딩하지 마라.** 목록 길이는 `Data` 에서 읽는다.
