# 재접속 알림(푸시) 설계

방치형 게임의 리텐션은 "다시 들어올 이유를 제때 알려 주는가"에 크게 달려 있다.
웹은 앱이 완전히 닫히면 스스로 알림을 못 띄우므로, **언제·무슨 알림을 띄울지**는 게임이 계산하고
**실제 예약·발송**은 앱 래퍼(또는 PWA 서비스워커)가 맡는다. 이 문서는 그 경계를 정의한다.

## 게임이 주는 것 — `Game.nextNudge()`

`nowDate()` 기준으로 앞으로 띄우면 좋은 알림 목록을 `inSec`(지금부터 몇 초 뒤) 오름차순으로 돌려준다.
순수 함수라 상태를 바꾸지 않으며, 저장·백그라운드 진입 시 언제든 다시 불러도 된다.

```js
[
  { id: 'offline_full', inSec: 14400, title: '가게가 손님으로 꽉 찼어요! 💰',
    body: '자리가 다 찼어요. 지금 들어와 그동안 쌓인 매출을 챙기세요.' },
  { id: 'daily',        inSec: 61200, title: '오늘의 출석 보상이 기다려요 🎁',
    body: '출석 도장 찍고 별사탕 받기 · 행운의 룰렛 무료 스핀도 새로 왔어요.' }
]
```

| id | 트리거 | 왜 |
|---|---|---|
| `offline_full` | 오프라인 매출 상한(`offlineCapSeconds()`)을 꽉 채우는 순간 | 더 비워 둬도 손해라, 들어올 이유가 가장 크다 |
| `daily` | 다음 날 오전 9시 | 새 출석 보상·룰렛 무료 스핀·오늘의 특선. 자정이 아니라 아침이라 새벽에 안 깨운다 |

상한 시간은 명성 업그레이드(`f_offtime`)로 늘어나므로 `inSec` 은 세이브마다 다르다.
목록은 언제든 늘어날 수 있으니(주간 이벤트 등) 래퍼는 `id` 로 구분해 처리한다.

## 앱 래퍼가 할 것 — `window.BunsikNative`

앱이 백그라운드로 갈 때(`visibilitychange → hidden`) 게임은 이미 `Game.nextNudge()` 를 계산해
브릿지가 있으면 넘긴다. 래퍼는 이 인터페이스만 구현하면 된다.

```js
window.BunsikNative = {
  // 넘겨받은 목록을 로컬 알림으로 예약한다. 매 호출은 이전 예약을 대체(취소 후 재등록)한다.
  scheduleNudges: function (list) { /* 네이티브 로컬 알림 API 로 각 inSec 뒤 예약 */ }
};
```

- **예약 대체**: 앱을 열 때마다(포그라운드 복귀) 게임이 다시 호출하므로, 매번 기존 예약을 지우고 새로 깐다.
- **권한**: 최초 1회 알림 권한을 요청한다. 거부해도 게임은 그대로 돌아간다(알림만 없음).
- **탭/그룹**: `tag = 'bunsik-' + id` 로 같은 종류 알림은 덮어쓴다(중복 방지).
- 브릿지가 없으면(순수 웹) 게임은 조용히 웹 단독 폴백(탭이 살아 있는 동안만 `offline_full` 하나)만 쓴다.

## 구현 경로별 메모

- **Capacitor / Cordova**: `@capacitor/local-notifications` 로 `scheduleNudges` 를 구현. `schedule.at = new Date(Date.now()+inSec*1000)`.
- **TWA(안드로이드 Trusted Web Activity)**: 웹 푸시(서버+서비스워커)가 필요하다. 서버가 유저별 `nextNudge` 시각에 푸시를 쏘거나, 간단히는 앱 셸에서 로컬 알림을 예약.
- **PWA 단독**: 서비스워커 + Push API. iOS 는 홈 화면 추가 + iOS16.4+ 에서만 웹 푸시가 되므로 커버리지가 낮다 → 스토어 앱(래퍼)이 확실하다.

## 빈도 원칙 (과하면 역효과)

- 하루 **2건 이하**. `offline_full` + `daily` 로 충분하다.
- 밤(오후 10시~오전 8시)에는 띄우지 않는다. `daily` 를 오전 9시로 둔 이유.
- 설정에서 언제든 끌 수 있어야 한다(`notifyOffline` 세이브 필드가 이미 있다).
