# 디자인 파이프라인 — Scenario(아트) × Figma(화면 설계) × Figma Make(프로토타입)

> 작성일 2026-09-02. 이 문서는 **아직 안 된 두 작업 — 그림 통일과 화면 설계 — 를 어떤 도구로 어떤 순서로 할지**를 정한다.
> 입력 문서: `docs/기능정의서-전체.md`(무엇을 그리나), `docs/화면정의서.md`(어떤 화면·컴포넌트가 있나), `docs/art-prompts.md`(부족한 그림 66장 명세).

---

## 0. 한 장 요약 — 순서가 전부다

```
① 기능정의서·화면정의서 확정 (문서)            ← 이번 주
② Scenario: 스타일 모델 학습 → 부족한 그림 66장 + 신규 UI 아이콘 생성
③ Figma Design: 토큰·컴포넌트 라이브러리 먼저 (화면정의서 §5·§6 이 초안)
④ Figma Design: P0 화면 정적 설계 (390×844, 상태 변형 포함)
⑤ Figma Make: ④의 프레임을 붙여 클릭 가능한 플로우 프로토타입 → figma.site 링크로 지인 테스트
⑥ 개발 핸드오프: Figma MCP 로 토큰·컴포넌트를 apps/client(Svelte)에 구현
```

**Figma Make 부터 시작하지 않는다.** Make 는 자체 라이브러리 기준의 범용 스타일을 내놓으므로, 우리 토큰·컴포넌트가 먼저 있어야 결과가 "우리 게임"처럼 나온다. 또 Make 는 프로토타입 도구라 방치형의 100ms 갱신 루프·세이브·이벤트 연출 같은 상태 로직을 담는 곳이 아니다. **화면의 생김새와 흐름을 검증하는 데만 쓴다.**

## 1. Scenario — 그림을 한 손으로 그린 것처럼

### 1.1 왜 Scenario 인가

- 이미 손그림 PNG 147장(`assets/img/food` `skin` `fame` `owner` `cust` …)이 있고, `docs/art-prompts.md` 가 부족한 66장(도전과제 37 · 파티 음식 · 기록 · 퀘스트 · 부대찌개)의 파일명·대상·팔레트를 정해 놨다.
- 범용 생성기로 66장을 뽑으면 기존 147장과 톤이 어긋난다. Scenario 는 **우리 그림으로 스타일 모델(LoRA)을 학습**해 같은 손으로 그린 듯한 결과를 내는 데 특화된 도구다. 커스텀 모델은 10~20장으로 30분~2시간에 학습되고, 학습된 모델은 생성 화면·워크플로 노드·API 어디서나 쓸 수 있다.

### 1.2 학습 방법 (Style Model)

| 단계 | 할 일 | 우리 프로젝트 적용 |
|---|---|---|
| **데이터셋 선별** | 10~20장. "같은 작가 손" 느낌의 12장이 섞인 40장보다 낫다. 주제·구도·줌은 다양하게, 스타일은 하나로 | `assets/img` 에서 **음식 6 · 스킨 4 · 손님 3 · 명성상점 3 · 소품 2 = 18장** 고른다. 이모지 폴백 자리나 톤이 다른 초기 그림은 제외 |
| **해상도** | 최소 1024×1024. 작은 그림은 내장 "Enhance 2x" 로 업스케일 | 기존 PNG 가 350~530px 이므로 **전부 2x 업스케일 후 투입** |
| **캡션** | 자동 캡션을 검토해 **스타일이 아니라 내용**(대상·자세·배경)만 적는다. 스타일을 글로 쓰면 모델이 키워드에 묶인다 | "a bowl of tteokbokki on a white plate, centered, transparent background" 식. 트리거 단어 하나(예 `bunsikart`)는 선택 |
| **베이스 모델** | Flux 2 기본(품질/비용 균형). Z-Image(속도), Qwen Image(비용) | Flux 2 |
| **파라미터** | 기본값(LR 1e-4, TE-LR 1e-5, batch 1, repeats 20, epochs 10). 5~10장이면 LR 5e-5 · epochs 15~20, 25~50장이면 2e-4 · 6~8 | 18장 → **기본값** |
| **테스트 프롬프트** | 최대 4개. 에폭마다 1장씩 뽑아 비교 그리드를 만들어 준다 | `art-prompts.md` 템플릿에서 4개: 배지(도전과제), 음식(부대찌개), 기록 아이콘, 파티 음식 |
| **에폭 선택** | 마지막 에폭이 기본이지만 **더 이른 에폭이 나은 경우가 많다.** 과적합(학습 구도를 그대로 재현) vs 과소적합(스타일 안 묻음) 사이 "스윗 스팟" | 4개 테스트 프롬프트 모두에서 팔레트·외곽선 `#2f3540`·위에서 오는 빛이 유지되는 에폭 |
| **소요** | 30분~2시간 | |

**피해야 할 것**: 두 스타일 혼합, 목표 톤 밖의 레퍼런스 포함, 캡션에 스타일 서술, 같은 대상만 반복.

### 1.3 생성·후처리 파이프라인

1. **프롬프트**: `art-prompts.md` 의 템플릿(굵은 차콜 외곽선, 위에서 오는 부드러운 빛, 적은 채도색, 4각 반짝이, 투명 배경, 바닥 그림자 없음, 512×512)에 "그릴 대상"만 갈아 끼운다. 스타일 모델을 쓰면 템플릿의 스타일 문구는 **줄여도** 된다(모델이 이미 알고 있다).
2. **세트 통일**: 도전과제 37장·기록 8장은 "둥근 금테 배지 위 오브젝트" 로 한 세트로. 같은 시드 범위·같은 모델·같은 에폭으로 한 번에 배치 생성(Workflow 노드 사용).
3. **배경 제거 → 512 정사각 → 20~30px 축소 확인**: 작은 크기에서 실루엣이 읽히는지 본다(HUD·칩·목록에서 20~84px 로 뜬다).
4. **파일명은 코드와 1:1** (`achv/ac1.png` …). 폴더에 넣으면 끝. 현재 main 은 `'이모지|경로'` 폴백 배선이 **없으므로**(그 브랜치는 병합 시 대체됨) 도전과제는 `data.js` 의 `icon` 을 이모지에서 경로로 바꾸는 한 줄 수정이 함께 필요하다.
5. **사장 캐릭터**: 성별 2 × 단계별 성장 이미지는 스타일 모델이 아니라 **캐릭터 모델**(같은 인물, 다양한 자세)로 따로 학습하면 단계 간 얼굴이 유지된다. 두 모델은 **Merge** 로 합칠 수 있다.

### 1.4 학습 로드맵 (1주)

| 일차 | 목표 | 산출 |
|---|---|---|
| 1 | Scenario UI 익히기: 기본 모델로 템플릿 프롬프트 10장 생성, 배경 제거·업스케일 도구 위치 파악 | 톤 비교용 샘플 |
| 2 | 데이터셋 18장 선별·2x 업스케일·캡션 수정 | 데이터셋 |
| 3 | 스타일 모델 학습(테스트 프롬프트 4개) → 에폭 비교 → 선택 | `bunsik-style v1` |
| 4 | Workflow 로 도전과제 37장 배치 생성 → 배경 제거 → 512 → 축소 확인 → 재생성 목록 | `achv/*.png` |
| 5 | 나머지 29장 + 신규 UI 아이콘(HUD 4개: 상점·우편·공지·룰렛은 아직 이모지) | 66+장 완료 |
| 6~7 | 사장 캐릭터 모델(선택) · 모델 카드 문서화(데이터셋·에폭·프롬프트 기록) | `docs/art-model-card.md` |

### 1.5 판단 기준

- **합격**: 새 그림을 기존 147장 사이에 섞어 놓고 어느 것이 새 것인지 구분이 안 될 때.
- **불합격 신호**: 외곽선 굵기 불일치, 바닥 그림자, 배경 잔여, 팔레트 밖 색, 30px 에서 형태 붕괴.

### 2.1 라이브러리(파일 1) — `화면정의서.md` §5·§6 을 그대로 옮긴다

| 층 | 내용 | 원천 |
|---|---|---|
| **토큰** | 색(배경·표면·강조·금색·초록·위험), 테마 3종(기본·포장마차·중화풍) 모드, 간격 4/8/12/16, 반경, 폰트 크기 단계, safe-area 상·하 | `style.css` CSS 변수, `data.js THEMES` |

컴포넌트 이름은 코드 id 와 맞춘다(`item-row`, `hud-chip/fame`, `modal/ask`). 나중에 Figma MCP 로 코드 매핑(Code Connect)할 때 그대로 쓰인다.

### 2.2 화면(파일 2) — 390×844, 상태 변형까지

- 우선순위는 `화면정의서.md` §8 체크리스트를 따른다. **P0**: HUD, 가게 탭(조리 영역 + 시트 접힘/펼침), 업그레이드, 환생 + 명성 상점, 하단 탭바, ask/text 모달, 토스트. **P1**: 주방(재료·레시피·등급 탭·도감 컬렉션·추천 바), 기록(퀘스트·출석부·랭킹·미슐랭·명예의 전당), 오프라인·출석·룰렛·광고 모달. **P2**: 설정(스킨·테마·소리·저장), 상점·우편·공지, 절전, 투어.
- 각 화면은 **상태 변형을 프레임으로**: 빈 상태 / 잠김(해금 조건 문구) / 구매 가능 / 구매 불가 / 완료 / 뱃지. 이것이 없으면 Make 가 상태를 지어낸다.
- Auto Layout·제약·레이어 이름 정리는 Make 품질에 직결된다(Figma 공식 팁: "Suggest Auto Layout", "Rename layers with AI" 로 먼저 정리).

## 3. Figma Make — 흐름 검증용 프로토타입

### 3.1 무엇이고 무엇이 아닌가

| Make 가 잘하는 것 | Make 에 기대하지 말 것 |
|---|---|
| 프레임을 붙이면 **구조 데이터**(스크린샷 아님)를 읽어 React+Tailwind 클릭 프로토타입 생성 | 프로덕션 코드 (접근성·시맨틱 미흡, 그대로 안 옮긴다) |
| 포인트-앤-에딧으로 색·폰트·반경·간격 즉시 수정, 코드 탭 "go to source" | 복잡한 상태 로직·조건 분기·다단계 플로우(방치형 루프·세이브·이벤트 타이머) |
| `*.figma.site` 로 공개 → 지인이 폰으로 바로 눌러봄 | 우리 디자인 시스템 자동 반영 — **Make kit**(React npm 패키지) 없으면 범용 스타일. 프레임·컴포넌트를 붙여 시각 레퍼런스로 주는 것이 현실적 대안 |
| 가짜 데이터 넣어 실감 있게(초당 수익·순위 등) | Make → Figma Design 왕복("Bring to Figma Design"은 있지만 편집 가능한 레이어로의 매끄러운 왕복은 아직 아님) |

플랜: Full seat 필요, 2026-03 부터 AI 크레딧 제. 크레딧을 아끼려면 **첫 프롬프트에 정보를 몰아넣고, 후속은 작게** 쪼갠다.

### 3.2 작업 순서

1. **한 플로우 = 한 Make 파일.** 화면정의서 §3 의 플로우 5개(첫 실행 → 첫 환생 → 하루 루프 → 주방 합성 → 이벤트 대응) 중 P0 두 개부터.
2. **프레임 붙이기**: Figma Design 의 해당 화면 프레임(상태 변형 포함)을 복사해 프롬프트 박스에 붙인다. 컴포넌트도 함께 붙여 "이 버튼·칩을 써라" 고 지시.
3. **첫 프롬프트 템플릿** (아래 §3.3).
4. **후속 프롬프트는 하나씩**: "시트를 위로 드래그하면 펼쳐지게", "잠긴 탭은 탭바에서 숨겨", "구매 불가 행은 회색".
5. **포인트-앤-에딧**으로 시각 미세조정. 생성 결과가 라이브러리와 어긋나면 프롬프트가 아니라 **Design 파일을 고친 뒤 다시 붙인다**(원천은 항상 Design).
6. **publish → figma.site 링크**로 지인 테스트. 피드백은 화면정의서 §7 의 "가설" 항목과 대조해 확정/기각 표시.
7. 확정된 화면은 Design 파일이 원천. Make 코드는 버린다.

### 3.3 첫 프롬프트 템플릿 (한국어로 써도 된다)

```
[역할] 모바일 방치형 게임 "분식집 키우기"의 클릭 프로토타입을 만든다.
[기기] 390×844 세로 고정, 상단 노치·하단 홈바 안전영역 확보, 가로 스크롤 금지, 다크 테마.
[구조] 상단 HUD(돈·초당수익·명성칩·배율칩·별사탕·쿠폰 / 아이콘 4개: 상점·우편·공지·룰렛)
      + 본문 + 하단 탭 6개(가게·업그레이드·주방·환생·기록·설정). 잠긴 탭은 숨김.
[이 파일의 범위] 가게 탭만. 위 60%는 조리 영역(큰 음식 그림을 탭하면 +금액 플로팅, 콤보 게이지),
      아래 40%는 "설비 & 직원" 시트. 시트는 손잡이를 위로 밀면 펼쳐지고 그동안 조리 버튼은 작아진다.
      시트 안에는 추천 바 → 손님 몰이 버튼 → ×1/×10/최대 토글 → 설비 목록(아이콘·이름·개수·초당수익·가격 버튼).
[상태] 첨부 프레임의 변형을 그대로: 구매 가능(초록 가격), 구매 불가(회색), 잠김(해금 조건 문구).
[데이터] 가짜 값: 돈 12.4만원, 초당 488원, 설비 6종, 첨부 표 참고.
[스타일] 첨부한 컴포넌트(버튼·칩·아이템 행·시트 핸들)를 그대로 쓴다. 새 스타일을 만들지 말 것.
[제외] 실제 타이머·세이브·사운드는 만들지 않는다. 탭하면 숫자만 오르면 된다.
```

### 3.4 방치형 게임에서 특히 확인할 것 (프로토타입 검증 체크리스트)

- 한 손 조작: 자주 누르는 것(조리·구매·손님 몰이)이 화면 아래쪽에 있는가
- HUD 밀도: 칩 5개 + 아이콘 4개가 390px 에서 겹치지 않는가 (최근 HUD 겹침 버그의 원인)
- 시트 접힘/펼침 두 상태에서 조리 영역이 계속 눌리는가
- 모달 11개가 같은 박스지만 **우선순위**(부팅 시 기존 유저: 오프라인 정산 → 출석, 신규: 투어 → 출석 — 화면정의서 §4.1)가 프로토타입에서도 그 순서인가
- 잠긴 탭·잠긴 항목의 해금 문구가 "무엇을 하면 열리는지"를 말하는가
- 등급 배지(초/중/고급)·별★·뱃지 dot 이 20px 대에서 읽히는가

## 4. 핸드오프 — Figma → 코드

- 이 개발 환경에는 **Figma MCP** 가 연결되어 있다. 확정된 Design 파일의 URL 을 주면 토큰·컴포넌트·화면 컨텍스트를 읽어 `apps/client`(Svelte)에 구현하고, Code Connect 로 컴포넌트 ↔ 코드 매핑을 남길 수 있다. Make 의 React 코드는 거치지 않는다.
- 아트는 Scenario 산출 PNG 를 `assets/img` (v2 에서는 client 에셋 매니페스트) 로. 파일명 규칙은 `art-prompts.md`.
