## 1. 현재 구조 진단 — 왜 그대로 서버에 못 올리나

| # | 현상 (main) | 위치 | 서버 분리 시 문제 |
|---|---|---|---|
| 1 | 세이브 하나를 모듈 전역 `S()` 로 참조 | `game.js` 전체 | 동시 사용자 N명을 한 프로세스에서 처리 불가 |
| 2 | 수익 캐시 `bump()`/`invalidate` 가 모듈 전역 | `game.js calc()` | 사용자 간 캐시 오염 |
| 3 | 콤보·매크로 감시 버퍼가 모듈 전역 | `game.js MACRO`, combo | 같은 이유 |
| 4 | `Date.now()` 직접 호출 (출석·퀘스트·트럭·특선·광고·룰렛 날짜) | `game.js`, `state.js` | 기기 시계 조작으로 일일 보상 무한 수령 |
| 5 | `Math.random()` 직접 호출 (황금손님·도둑·트럭 재료·룰렛·파티 음식) | `game.js` | 클라가 보상을 스스로 결정 → 조작 가능, 재현 불가 |
| 6 | 도전과제 조건이 **함수(클로저)** | `data.js ACHIEVEMENTS.check` | JSON 으로 내려줄 수 없음 |
| 7 | 손그림 SVG 문자열·이미지 경로가 밸런스 데이터와 한 파일 | `data.js` | config 와 에셋이 분리돼야 함 |
| 8 | 공지·우편·상점 목록이 코드 상수 | `data.js NOTICES/MAIL/SHOP` | 운영 콘텐츠는 서버에서 내려와야 함 |
| 9 | 매크로 방지의 1차 근거가 `event.isTrusted` | `game.js tap()` | 서버는 신뢰 못 함. 서버측 상한으로 대체 |
| 10 | 랭킹·미슐랭 보드가 시드 기반 가상 | `game.js rankBoard/michBoard` | 실제 랭킹으로 교체 |

**그러나 규칙 자체는 검증됐다.** `tests/logic.js` 133항목(단정 427개), 진행 속도 시뮬, 매크로 오탐 0% 는 그대로 v2 의 회귀 테스트 자산이 된다. 버리는 것은 *구조*이고, 살리는 것은 *규칙과 수치*다.

### 2.1 `packages/config` — 밸런스는 데이터

- `data.js` 의 상수(`GENERATORS` `UPGRADES` `FAME_SHOP` `GOLDEN` `THIEF` `BOOST` `OFFLINE` `DAILY` `CANDY` `ROULETTE` `SHOP` `KITCHEN` `COUPON` `MICHELIN` `RANK` `QUEST(S)` `ACHIEVEMENTS` `PARTY` `ADS` `TAP_STEP_AT` `CROWD_TIER_AT` `MANAGER` `FIRST_PRESTIGE`)를 **값만** 옮긴다. SVG·이미지 경로·테마·스킨은 클라이언트 에셋 매니페스트로 분리.
- **도전과제·퀘스트·업그레이드 해금 조건은 선언적으로**:
  ```ts
  { id: 'ac2', cond: { stat: 'taps', gte: 100 } }
  { id: 'u12', unlock: { allOf: [{ gen: 'g3', gte: 10 }, { stat: 'runEarned', gte: 1e6 }] } }
  ```
  `sim` 이 `evalCond(state, cond)` 하나로 평가한다. 지금 `check: function(s)` 클로저 37개는 전부 이 형태로 표현 가능하다(모두 `s.필드 >= 값` 또는 설비 개수 비교).
- `CONFIG_VERSION` 을 붙이고, 서버 `GET /v1/config` 가 내려준다. 클라는 캐시 + 버전 비교. **앱 재배포 없이 수치 조정**이 목적.

### 2.2 `packages/sim` — 순수 시뮬레이션 코어

```ts
type Ctx = { now: number /*ms, 서버 시각*/, rng: Rng /*시드 기반*/, cfg: Config, tz: 'Asia/Seoul' };
type Result = { state: State; events: Event[]; rejected?: string };

apply(state: State, action: Action, ctx: Ctx): Result
tick(state: State, untilMs: number, ctx: Ctx): Result      // 지연 계산 — now - lastTickAt 만큼 한 번에
derive(state: State, cfg: Config): Derived                 // perSec·tapValue·stat 배율 등 (캐시 없음, 순수)
```

- **캐시 제거**: 지금 `calc()` 캐시는 100ms 루프가 매번 업그레이드 65종을 훑는 비용을 피하려는 것이다. 서버는 요청당 한 번만 계산하므로 캐시가 필요 없다. 클라는 `derive()` 를 상태가 바뀔 때만 부른다(Svelte 파생 스토어). → **CLAUDE.md 규칙 1 `Game.invalidate()` 사고 부류가 구조적으로 사라진다.**
- **콤보**는 클라 연출 + 서버 검증 값으로 분리한다: 클라가 배치에 `comboPeak` 를 보내고, 서버는 `min(comboPeak, count)` 로 상한을 씌워 인정한다(1.2초 간격 규칙은 배치 내 `count`/`durationMs` 로 검증).
- **난수**: `Rng` 는 `state.seed` 를 시드로 하는 결정적 PRNG(xoshiro/mulberry32). 서버가 시드를 갱신하고, 같은 세이브 + 같은 액션 로그로 **완전 재현**된다. 지금 `daySeed`(날짜 시드 퀘스트·특선·랭킹 보드) 방식은 이미 이 철학에 맞으므로 그대로 승격.
- **시간**: `ctx.now` 만 본다. 자정 판정은 `Asia/Seoul` 고정(지금은 기기 로컬 자정).

### 2.3 상태 스키마 (`sim/state.ts`, Zod)

- `state.js fresh()` 의 필드(약 95개)를 그대로 타입으로 옮기되 세 묶음으로 나눈다.

| 묶음 | 예 | 저장 | 비고 |
|---|---|---|---|
| **core** (수치·진행) | money, gens, upgrades, fame, fameLv, achievements, kfoods, ings, coupons, candy, runs, quest*, att*, mich* | Postgres `saves.state jsonb` + Redis 핫 | 서버 권위 |
| **prefs** (취향) | tapSkin, crowdSkin, theme, tapSound, mute, ownerSex, sheetUp, notifyOffline | Postgres `users.prefs` | 검증만, 수치 무관 |
| **client-only** | sawTour, sawPrestigeIntro, sawCouponTip, tabsSeen, lastBackup | 기기 localStorage | 서버 저장 안 함 (기기별) |

- `v: 3` → `v: 4` 마이그레이션(`sim/migrate.ts`): 기존 `localStorage` 세이브·백업 코드(base64)를 **그대로 가져오기** 지원. `normalize()` 의 검증 규칙(유효 id 만, 상한 clamp, 배열 길이 짝, Infinity 천장)을 Zod 스키마 + `migrate` 로 옮긴다. 이것이 지인 테스트 세이브를 잃지 않는 유일한 길이다.
- **숫자 타입 결정**: 현재 `earn()` 이 1e308 천장을 두고 있고 `Fmt` 가 극(1e48)까지 표기한다. 시뮬 기준 3일에 초당 5억, 명성 상점 만렙이 9667조 명성이다. `double`(약 1.8e308) 안에서 충분하므로 **`number` 유지 + 서버에서도 동일 천장**을 권장한다. `break_infinity` 는 후반 콘텐츠가 극을 넘게 설계될 때만 도입한다(그때는 산술 전체가 뒤집히므로 지금 결정을 기록해 둔다).

### 2.4 서버 발행 이벤트 티켓 — 황금 손님·도둑·트럭·파티 음식

지금은 클라가 `rollGolden()`/`nextThiefGap()` 으로 등장을 굴리고 보상까지 정한다. 서버 권위로 바꾸면:

1. `tick()` 이 `ctx.rng` 로 다음 등장 시각·종류를 정해 `state.pendingEvents[]` 에 **티켓**을 넣는다: `{id, kind:'golden'|'rainbow'|'thief'|'truck', at, expiresAt, payload}`.
2. 클라는 상태 동기화로 티켓을 받아 **연출만** 한다(9초 안 탭, 7.5초 추격, 12초 트럭).
3. 사용자가 잡으면 `claimEvent{eventId}` → 서버가 만료·중복 검사 후 보상 적용. 놓친 티켓은 다음 `tick` 이 정리(도둑은 그때 손실 확정).
4. 경찰 자동 검거(`policeChance`)도 서버가 티켓 생성 시 결정해 `payload.policeCatches` 로 내려준다.

효과: 보상 조작 불가, 티켓이 로그에 남아 재현 가능, 클라는 순수 연출 계층이 된다(`scene.js` 철학과 일치).

### 2.5 동기화 프로토콜 — 로컬 예측 + 서버 보정

```
클라: 액션을 로컬 sim 에 즉시 적용(예측) → 큐에 쌓음
      5초마다 또는 큐 20개마다  POST /v1/actions { since: rev, actions: [...] }
서버: state = load(user); tick(state, now); for a in actions: apply(...)
      save; return { rev, state (또는 diff), events, rejected: [{idx, reason}] }
클라: rev 비교 → 서버 상태로 교체(rejected 가 있으면 토스트)
```

- 방치형은 UI 에 보이는 `money` 가 초당 수십 번 바뀌지만 **서버 왕복은 0.2 rps** 로 충분하다(v2 README 계산). 오프라인 시엔 큐를 로컬에 보관하고 재접속 시 전송(서버가 `ctx.now` 로 시간 검증하므로 조작 불가).
- `rev` 는 사용자별 단조 증가. 멱등성: 각 배치에 `batchId`(UUID)를 붙여 재전송 시 중복 적용 방지.
- 실시간 채널(WebSocket)은 **불필요**. 랭킹·우편 갱신은 폴링(60초)으로 족하다.

### 2.6 매크로 방지의 이관

| 지금 (클라) | v2 |
|---|---|
| `isTrusted` 검사 | 클라 연출 계층에만 남김(서버는 안 믿음) |
| 초당 14회 상한 | **서버**: `tapBatch.count ≤ ceil(durationMs/1000 × 14)` 초과분 폐기 |
| 간격 CV + 좌표 2px 휴리스틱 | 클라에서 유지(즉시 피드백) + 서버는 배치 통계(count/duration 분포)로 이상 계정 **플래그만** (차단은 운영 판단) |

"사람을 잘못 막는 쪽이 더 나쁘다"는 README 원칙을 유지하려면 서버는 상한만 강제하고 판정형 차단은 하지 않는다.

## 3. 데이터 모델 (Postgres)

```sql
users        (id uuid pk, created_at, auth_provider, provider_uid, device_key_hash, prefs jsonb, region text, banned_at)
saves        (user_id pk fk, rev bigint, state jsonb, state_v int, last_tick_at timestamptz, updated_at)
action_log   (id bigserial, user_id, rev, batch_id uuid unique, actions jsonb, applied_at, rejected jsonb)  -- append-only, 30일 보관
events       (id uuid pk, user_id, kind, issued_at, expires_at, payload jsonb, claimed_at)               -- 티켓 (또는 state 안에 두고 로그만)
seasons      (id text pk 'YYYY-MM', kind 'michelin', starts_at, ends_at)
season_scores(season_id, user_id, stars, taps, updated_at, pk(season_id,user_id))
mail         (id, user_id null=전체, title, body, reward jsonb, starts_at, ends_at)
mail_claims  (mail_id, user_id, claimed_at, pk)
notices      (id, title, body, published_at)
config_versions (version int pk, payload jsonb, published_at)
purchases    (id, user_id, store 'apple'|'google'|'pg', product_id, receipt_hash unique, status, amount, currency, created_at)
ledger       (id, user_id, currency 'candy'|'coupon'|'gold', delta, reason, ref_id, created_at)        -- 재화 원장, 결제·보상 모두 기록
ad_rewards   (id, user_id, slot, network_tx_id unique, verified_at)                                      -- SSV 콜백
```

- **Redis**: `sess:{token}`, `save:{user}`(핫 상태, write-behind 5초), `rank:global` / `rank:region:{r}` ZSET(score = `rankScore`), `rl:{user}` 레이트리밋, `mich:{season}` ZSET.
- 랭킹 점수는 **서버가 `derive()` 로 계산한 값만** ZSET 에 넣는다. 지금 `rankScore = 수익·환생·도감 합산` 공식을 그대로 쓰되, 지역(`region`)은 가입 시 서버가 배정한다.

## 5. 클라이언트 (`apps/client`)

- **프레임워크: Svelte 5 권장.** 근거는 v2 README 와 같다 — `money` 가 rAF 마다 바뀌는 방치형에서 세밀한 반응성이 필요하고, React 는 memo/ref 와 씨름한다. 번들이 작아 Capacitor 부팅도 빠르다.
- 구조는 스캐폴딩대로 `adapter/local | remote`, `ui/`(선언형), `scene/`(명령형 유지 — 거리·황금손님·도둑 연출은 프레임워크로 옮기면 오히려 길어진다).
- 옛 코드에서 **그대로 가져올 것**: `format.js`(만·억·조…극 표기, 대체 라이브러리 없음), `sound.js`(WebAudio 합성 — 음원 파일 없음 원칙), `sky.js`(12분 하루 시계), 거리 연출 규칙(손님은 오른쪽에서 와서 가게 앞에서 돌아나감, 전신 이모지/PNG 만).
- **화면은 Figma Make 결과물이 아니라 Figma Design 의 토큰·컴포넌트를 기준으로 구현**한다(`docs/디자인-파이프라인-Scenario-FigmaMake.md` §2). Make 의 React+Tailwind 코드는 참고용이며 그대로 옮기지 않는다.
- 아티팩트/웹뷰 규칙 유지: `confirm/prompt` 금지, `[hidden]` 규칙, safe-area 변수.

## 6. 모바일 (`apps/mobile`, Capacitor)

- client 빌드를 **번들**(URL 로딩 아님 — 애플 4.2 회피). 밸런스는 `/config` 로 받으므로 수치 조정은 심사 없이 가능. 웹 자산 OTA 로 화면 수정도 심사 없이.
- 네이티브 필수 4종: 푸시("오프라인 수익 가득"), IAP, 네이티브 저장소(localStorage 회수 대비 — 서버 권위가 되면 중요도↓), 햅틱.
- 스토어 정책 리드타임(개발자 계정, D-U-N-S, 구글 클로즈드 테스트 20명×14일, GRAC 자체등급분류, 확률형 아이템 확률 공개)은 v2 README 의 목록을 그대로 따른다. **룰렛은 확률형 아이템 공시 대상**이므로 확률표를 config 에 두고 화면에 노출한다(지금 `ROULETTE` 칸별 가중치가 그 원본).

## 7. 마이그레이션 순서 — 재작성이 아니라 "옮겨 심기"

전면 재작성은 규칙을 다시 틀릴 위험이 크다. **`game.js` 를 함수 단위로 `sim` 에 옮기고, 옮긴 만큼 `tests/logic.js` 의 해당 단정을 Vitest 로 이식해 같은 값이 나오는지 확인**하는 방식을 택한다.

| 단계 | 산출물 | 완료 기준 | 기획 의존 |
|---|---|---|---|
| **0. 기획 동결** | `기능정의서-전체.md` 확정, 액션 카탈로그(§2.2) 승인 | 2주간 기능 목록 변경 없음 | ★ |
| **1. config 이식** | `packages/config` 에 data.js 수치 전부 + 선언적 조건 | `data.js` 와 값 1:1 대조 스크립트 통과 | 없음 |
| **2. sim 코어** | `derive()`: perSec·tapValue·stat 배율·가격·해금 | `tests/logic.js` 의 수익·가격 단정 이식 통과 | 없음 |
| **3. sim 액션** | 구매·환생·버프·쿠폰·주방·퀘스트·출석·룰렛·미슐랭 `apply()` | 나머지 logic.js 단정 이식 + 진행 속도 시뮬 재현 | 없음 |
| **4. tick·티켓** | 지연 계산, 오프라인, 점장, 이벤트 티켓, 시드 RNG | 오프라인 상한·버프 제외(규칙 5) 테스트 | 없음 |
| **5. migrate** | v3 → v4, 백업 코드 가져오기 | 지인 세이브 샘플 10개 무손실 | 없음 |
| **6. api 1~4** | 인프라·계정·관측·결제 원장 (스캐폴딩 README 순서) | 배포된 `/health`, 게스트 로그인 | 없음 |
| **7. api 5~6** | `/actions` `/state` `/config` 랭킹 | 로컬 sim 과 서버 sim 결과 해시 일치 | 3 완료 |
| **8. client** | Svelte + adapter/local 로 먼저 (서버 없이 지인 테스트 가능) → adapter/remote | Figma 디자인 P0 화면 구현 | 디자인 |
| **9. mobile** | Capacitor, 푸시, IAP | 클로즈드 테스트 트랙 | 8 완료 |

단계 1~5 는 **서버도 디자인도 필요 없다**. 지금 바로 시작할 수 있고, 디자인 작업(Scenario·Figma Make)과 완전히 병행된다.
