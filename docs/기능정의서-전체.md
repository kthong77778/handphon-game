## 1. 문서 개요

### 1.1 소스 우선순위

| 우선 | 파일 | 담당 |
|---|---|---|
| 1 | `assets/js/data.js` | 밸런스 수치 전부, 스킨/테마/공지/우편 데이터, 손그림 SVG |
| 2 | `assets/js/game.js` | 규칙(수익 계산 캐시, 버프, 콤보, 매크로 방지, 환생, 퀘스트, 랭킹, 파티, 스타 셰프, 주방, 룰렛, 출석, 광고, 우편, 상점) |
| 3 | `assets/js/state.js` | 세이브 스키마 `fresh()`, 검증 `normalize()`, 저장/내보내기/불러오기 |
| 4 | `index.html` · `assets/js/ui.js` | DOM id(UI 진입점), 모달, 연출(황금 손님·도둑·트럭 등장) |
| 5 | `assets/js/main.js` | 부팅 순서, 게임 루프(tick), 자동 저장, 자정 리셋 호출 |
| – | `assets/js/scene.js` `sky.js` `sound.js` `format.js` | 연출·하늘(게임 시계)·합성음·숫자 표기 (수치에 관여하지 않음) |

### 1.2 용어

| 용어 | 코드 | 뜻 |
|---|---|---|
| 조리(탭) | `Game.tap()` | 조리 버튼(`#tap`)을 누르는 기본 행동. 탭 수익을 즉시 얻는다 |
| 설비 | `Data.GENERATORS`, `s.gens` | 초당 수익을 내는 자동 생산 유닛 10종 |

| 명성 | `s.fame` | 환생으로 얻는 영구 재화. 명성 상점에서 소비 |
| 명성 상점 | `Data.FAME_SHOP`, `s.fameLv` | 명성으로 사는 영구 강화 |
| 환생(재개업) | `Game.doPrestige()` | 회차를 정리하고 명성을 받는 리셋 |
| 회차(run) | `s.runEarned`, `s.runTime`, `s.runs` | 환생과 환생 사이의 한 판 |
| 별사탕 | `s.candy` | 상점·룰렛 전용 재화. 환생해도 유지 |
| 쿠폰 | `s.coupons`, `s.couponPct` | 설비/업그레이드 ×1 구매 할인권 |
| 재료 | `s.ings` | 주방 레시피 소재 12종 |
| 도감 | `s.kfoods`(주방), `s.partyFoods`(파티) | 만든/발견한 음식 목록. 영구 배율 원천 |
| 사장 레벨 | `Game.bossLevel()` | 누적 매출(`s.totalEarned`)로 정해지는 플레이어 레벨. 레시피 해금 게이트 |
| 버프 | `s.boostLeft` `s.goldLeft` `s.goldTapLeft` | 시간제 배율. 온라인일 때만 줄어든다 |
| 초당 수익 | `Game.perSec(noBuff)` | 설비 합계 × 전체 배율. `noBuff=true` 면 버프 제외 |
| 세션 변수 | (게임 모듈 로컬) | 세이브되지 않고 새로고침 시 사라지는 값 (콤보, 트럭 타이머, 쿠폰 장전 등) |

| 날짜 시드 | `daySeed`, `hashStr` | 날짜 문자열에서 결정적으로 뽑는 난수. 새로고침으로 다시 뽑을 수 없다 |

### 1.3 표기 규칙

- 수치는 `상수명 = 값` 으로 쓴다. 상수가 `data.js` 밖에 있으면 파일을 붙인다 (예: `game.js COMBO_MAX = 50`).
- 시간 단위는 초(s) 기본. 분·시간은 괄호로 환산한다.
- "초당 수익 N분치" = `Game.perSec(true) × N × 60` (버프 제외). 보상 대부분이 이 형식이라 인플레이션에 안전하다.
- UI 진입점은 `index.html` 의 id(`#id`) 또는 `ui.js` 의 함수명으로 적는다. 화면 레이아웃은 [화면정의서.md](./화면정의서.md) 참조.

## 2. 게임 개요 & 핵심 루프

### 2.1 한 줄 요약

분식집을 탭으로 조리해 돈을 벌고, 설비·업그레이드로 초당 수익을 키우고, 회차가 커지면 **환생(재개업)** 으로 명성을 얻어 영구 강화하는 방치형 게임. 서버가 없는 정적 사이트(GitHub Pages)로, 세이브는 브라우저 `localStorage` 한 곳이다. 랭킹·스타 셰프 순위는 전부 **가상 상대와의 연출**이다.

### 2.2 세션 루프 (수 초 ~ 수 분)

```
조리 탭 ──▶ 콤보(1.2s 창) ──▶ 돈 ──▶ 설비 ×1/×10/최대 구매 ──▶ 초당 수익 ↑
   ▲                                   └─▶ 업그레이드(해금 조건) ──▶ 배율 ↑
   │  랜덤 이벤트: 황금 손님(55~130s) · 도둑(200~460s) · 재료 트럭(30s×n)
   │  수동 버프: 손님 몰이 ×3 60s (쿨 900s)
   └── 조리 메뉴 8단계 · 손님 등급 5단계 · 사장 레벨이 눈에 보이게 오른다
```

### 2.3 일일 루프 (실시간 자정 기준)

| 요소 | 리셋 | 보상 성격 |
|---|---|---|
| 30일 출석부 | 날짜가 바뀌면 다음 칸 수령 가능 | 초당 수익 N분치 + 별사탕 (+마일스톤 보너스) |
| 오늘의 퀘스트 3개 | 날짜 시드로 새로 깔림 | 초당 수익 420s치 ×3 + 완주 900s치 + 손님 몰이 충전 |
| 무료 보상(광고) 4슬롯 | 각 3회/일 | 수익 2배 30분 · 골드 1시간치 · 쿠폰 · 재료 12 |
| 행운의 룰렛 | 첫 스핀 무료 | 8칸 가중치 보상, 추가 스핀은 별사탕 5 |
| 오늘의 특선 / 단골 주문 | 날짜 시드 | 특선 목돈 ×3, 3회 만들면 초당 수익 1800s치 |
| 재료 트럭 횟수 | 0 으로 | 트럭 간격이 30s·60s·90s… 로 늘어나는 카운터 |
| 주말 파티 | 금·토 17~24시 | 수익 ×3, 황금 손님 2배, 탭당 3% 확률로 파티 음식 도감 |

### 2.4 장기 루프 (일 ~ 주)

1. **환생**: 회차 매출 ≥ `PRESTIGE_BASE = 1e6` 이면 가능. 명성 = ⌊(매출/1e6)^0.37⌋. 명성 1당 모든 수익 +2%.
2. **명성 상점** 11종 영구 강화 (오프라인 시간/효율, 점장, 야간 순찰, 분식 왕조 …).
3. **도전과제** 35종: 하나당 모든 수익 +1% 영구 + 별사탕 2.
4. **주방 도감**: 레시피 20종 발견·숙련·컬렉션 완성으로 영구 배율.
5. **스타 셰프 도전**: 월 시즌·티어 제도, 5성 첫 달성 시 모든 수익 ×1.5 영구.
6. **전국 맛집 랭킹**: 수익·명성·도감 3축 종합 점수로 가상 순위.
7. **명예의 전당**: 회차 기록 최근 50개, 개인 최고 기록.

## 4. 시스템별 기능 정의

각 시스템은 **목적 · 규칙 · 세이브 필드 · 트리거 · UI 진입점 · 예외/엣지** 순으로 적는다. 화면 구성은 [화면정의서.md](./화면정의서.md) 를 본다.

### 4.1 조리(탭) · 콤보 · 매크로 방지

**목적** — 게임의 기본 입력. 손으로 조리해 초반 종잣돈을 만들고, 후반에는 `tapPct` 업그레이드로 초당 수익의 일부를 탭마다 얹는다.

**규칙**

| 항목 | 값 / 공식 | 출처 |
|---|---|---|
| 탭 수익 | `tapValue() = tapBase × goldTapMult(활성 시) × comboMult × stat × buffMult + perSec() × tapPct` | `game.js tapValue()` |
| 단계 판정용 탭 수익(버프 제외) | `tapBaseValue() = tapBase × stat + perSec(true) × tapPct` | `game.js tapBaseValue()` (CLAUDE.md 규칙 4) |
| `tapBase` | 1 × ∏(kind='tap' 업그레이드 value) × 3^`f_tap` | `calc()` |
| `tapPct` | Σ(kind='tapPct' 업그레이드 value) = 최대 0.01+0.02+0.05 = 0.08 | `calc()` |
| 콤보 유지 창 | `COMBO_WINDOW = 1.2` s | `game.js` |

**UI 진입점** — `#tapZone` `#tapTarget` `#tapEmoji` `#tapLabel` `#tapPower`(탭당 수익), `#combo` `#comboX` `#comboN` `#comboFill`(콤보 게이지), `#pops`(플로팅 숫자), `showBlocked(reason)` 토스트.

**예외/엣지**
- 매크로가 꺼져 있으므로 현재 배포에서는 어떤 탭도 거부되지 않는다. 설정 탭 통계에 매크로 항목은 `macroGuardOn()` 이 true 일 때만 노출.
- `tapValue` 는 `perSec()`(버프 포함)을 쓰고 `tapBaseValue` 는 `perSec(true)` 를 쓴다 — 메뉴 단계가 버프로 흔들리지 않게 하기 위함.
- 절전 모드(§4.30) 중에는 조리 화면이 가려져 탭할 수 없다.

### 4.8 버프 중첩 규칙

| 슬롯 | 필드 | 채우는 곳 | 합치는 규칙 |
|---|---|---|---|
| 수익 버프(단일 슬롯) | `goldLeft` / `goldMult` | 황금 `rush`(×7/30s), 무지개(×5/20s), 광고 '수익 2배'(×2/1800s), 상점 '수익 2배'(×2/1800s) | `applyIncomeBuff(mult, dur)`: 비활성이거나 **새 배율이 더 크면 교체**(배율·시간 모두), 같은 배율이면 남은 시간을 `max`, 새 배율이 더 작으면 **무시**(기존 유지) |

`buffMult() = goldMult(활성) × BOOST.mult(활성) × PARTY.mult(파티 중)` — 세 슬롯은 **곱**으로 중첩된다. 콤보와 탭 버프는 `tapValue()` 에서만 곱해진다. 오프라인·출석·퀘스트 보상 등 "초당 수익 N초치" 계산은 전부 `perSec(true)`(버프 제외).

**UI** — `#buffBar` 에 `activeBuffs()` 순서(📣 몰이 → ⚡ 수익 → 👐 탭)로 남은 시간 표시. HUD `#multChip` 은 전체 배율.

### 4.12 오프라인 수익 (`OFFLINE`)

**목적** — 앱을 꺼둔 동안의 보상. 방치형의 핵심.

| 항목 | 값 / 공식 |
|---|---|
| 경과 | `elapsed = (now − s.lastSeen)/1000` (main.js) |
| 인정 시간 | `offlineCapSeconds = (4 + 2 × f_offtime) × 3600` → 기본 4h, 만렙(12) 28h |
| 효율 | `offlineEfficiency = 0.5 + 0.1 × f_offeff` → 기본 50%, 만렙(10) 150% |
| 꼬리 구간 | 2차 상한 `tailCap = cap × OFFLINE.tailMult(3)` (기본 12h, 만렙 84h). 인정 시간 초과분은 `OFFLINE.tailEff = 0.15` 효율로만 |
| 보상 | `gain = perSec(true) × eff × (capped + tailSeconds × 0.15)` — **버프 제외**(CLAUDE.md 규칙 5), 파티 배율도 미적용 |
| 재료 트럭 | `trucks = offlineTrucks(capped)` 대의 트럭이 지나간 것으로 쳐 `trucks × KITCHEN.missDrop(2)` 개 자동 수거(§4.24.1). 돈·쿠폰 드롭 없음 |
| 수령 | `claimOffline(gain, trucks)`: `earn`, `offlineClaims++`, `truckCount += trucks` |
| 버프/쿨 | `advanceTimers(elapsed)` 로 남은 시간·쿨다운을 경과분만큼 흘린다 |
| 점장 | 보상 직후 `runManager(elapsed)` (§4.13) |
| 알림 | 설정 `notifyOffline` = 1 이면 인정 시간이 가득 찼을 때 브라우저 알림 예약(`Notification`, 권한 필요) |
| 잘못된 경과 | `elapsed ≤ 0`·NaN 이면 보상 0, 트럭 0 |

**세이브 필드** — `lastSeen`(저장 시각), `offlineClaims`, `notifyOffline`.
**트리거** — `main.js` 부팅 시 경과 계산 → `UI.showOffline(reward, onOk)` 모달 → 확인 시 지급. (최소 경과 문턱은 main.js 참조 — §6)
**UI 진입점** — `#offlineModal` `#offlineText` `#offlineOk`, 설정 `#notifyBtn`.

### 4.13 점장 (`MANAGER`, 명성 상점 `f_manager`)

| 항목 | 값 |
|---|---|
| 구매 횟수 | `managerBuys = MANAGER.buysPerLv(2) × f_manager` → 만렙 20회 |
| 최소 부재 | `minOfflineSec = 300` s 미만이면 일하지 않음 |
| 잔액 보존 | `keepRatio = 0.25` — 시작 시점 보유액의 25% 는 남긴다(floor) |

### 4.25 할인 쿠폰 (`COUPON`)

| 적용 | 설비 **×1 구매**: `genCost − couponDisc × base`; 업그레이드: `cost × (1 − couponDisc)`. 구매 성사 시 `useCouponIfArmed()`: 쿠폰 −1, 장전 해제, 할인율 성장 |
| 미적용 | ×10/최대 구매 — 쿠폰 유지. UI 가 "×1 에만 적용" 토스트 |

## 5. 수익 계산 순서 (`calc()`, `tapValue()`, `perSec()`, `earn()`)

### 5.1 고정 배율 `stat` (버프 제외 · 캐시됨)

`calc()` 는 `cacheVer` 가 바뀔 때만 다시 계산한다. 세이브의 `gens · upgrades · fameLv · fame · achievements · kfoods · partyFoods · michelinGrand` 를 건드리면 `bump()`(= `Game.invalidate()`) 필수 (CLAUDE.md 규칙 1).

```
stat = 1
  × (1 + 0.02 × fame)                          명성 1당 +2%
  × (1 + 0.01 × achievementCount)              도전과제 1개당 +1%  (37종 → 최대 ×1.37)
  × 1.5 ^ fameLv.f_mult                        전설의 명성 (max 20 → ×3325)
  × 3   ^ fameLv.f_legend                      분식 왕조 (max 25 → ×8.47e11)
  × 1.05^ fameLv.f_research                    끝없는 연구 (상한 없음)
  × (1 + 0.01 × partyFoods.length)             파티 도감 (12종 → ×1.12)
  × (1 + foodBonus())                          주방 도감 Σ(bonus × gradeMult × masteryMult)  (전종 ★★★ → ×2.625)
  × collectionMult()                           도감 컬렉션 세트 (전부 → ×11.2)
  × 1.5 (michelinGrand 일 때)                  스타 셰프 5성 영구
  × ∏ value (kind='all' 업그레이드)             1.25·1.25·1.3·1.4·1.5·2 → 전부 ×8.53
stat = cap(stat)                               1e308 천장
```

설비별 배율 `genM[id] = ∏ value (kind='gen', target=id)` → 티어 I~V 전부 = ×48.
탭 기본 `tapBase = ∏ value (kind='tap') × 3^fameLv.f_tap` → 업그레이드 전부 ×720, `f_tap` max 15 → ×3^15.
`tapPct = Σ value (kind='tapPct')` → 최대 0.08.

### 5.2 초당 수익

```
base    = Σ_g ( rate_g × gens[g] × genM[g] ) × stat          ← cap()
perSec(noBuff) = cap( base × (noBuff ? 1 : buffMult()) )
buffMult = (goldLeft>0 ? goldMult : 1) × (boostLeft>0 ? 3 : 1) × (partyActive ? 3 : 1)
```

`tick(dt)` 는 `earn(s, perSec() × dt)` — 버프 포함. 오프라인·출석·퀘스트·룰렛·광고·상점·특선·스타 셰프·황금 손님 현금·도둑 목표액 등 "초당 수익 N초치" 는 모두 `perSec(true)`.

### 5.3 탭 수익

```
tapValue = tapBase × (goldTapLeft>0 ? goldTapMult : 1) × comboMult × stat × buffMult
         + perSec() × tapPct                                   ← perSec 은 버프 포함
tapBaseValue = tapBase × stat + perSec(true) × tapPct          ← 메뉴 단계 판정 · 황금 손님 바닥값 전용
```

콤보 `comboMult = 1 + min(combo,50) × 0.04`. 탭 배율(`goldTapMult`, 콤보)은 `tapPct` 항에는 곱해지지 않는다.

### 5.4 `earn()` 천장과 수치 안전장치

- `CAP = Number.MAX_VALUE`. `earn(s, amount)`: `amount` 가 유한하지 않거나 ≤ 0 이면 0 (단 `Infinity` 는 `CAP` 으로 치환), `money/runEarned/totalEarned` 각각 `cap()` 으로 더한다. 퀘스트 `earn` 진행도도 여기서 올린다.
- `calc()` 의 `stat`·`base`·`tapBase` 도 `cap()`. `atIncomeCap()`(`perSec(true) ≥ CAP`)이면 구매·추천을 막는다.
- 구매 검사는 전부 `!(money >= cost)` 형태(NaN fail-closed).
- `normalize()` 는 `money·runEarned·totalEarned·bestRunEarned·stolen` 을 `CAP` 으로 clamp, 그 외 수치는 유한·≥0 만 인정.
- `Fmt.num(Infinity)` 는 `∞` 로 표기(CLAUDE.md 규칙 10).

### 5.5 배율 적용 순서 요약표

| 단계 | 대상 | 항목 |
|---|---|---|
| 1 | 영구(환생 유지) | 명성, 도전과제, 명성 상점 3종, 파티 도감, 주방 도감, 컬렉션, 스타 셰프 5성 |
| 2 | 회차 | 업그레이드 `all`(stat), `gen`(genM), `tap`(tapBase), `tapPct` |
| 3 | 일시 | `buffMult` = 수익 버프 슬롯 × 손님 몰이 × 파티 |
| 4 | 탭 한정 | 탭 버프 × 콤보 |
| 5 | 천장 | `cap()` → `earn()` |
