## 1. 현황 진단

### 1.1 저장소

- **브랜치**: `main`(프로토타입, 지인 테스트 빌드) · `v2`(프로덕션 재작성용 모노레포 스캐폴딩, 코드 없음). 나머지 4개는 2026-09-02 에 병합·삭제했다.
- **코드 규모**: JS 8,188줄(`game.js` 2,307 · `ui.js` 2,963 · `data.js` 1,356 · `state.js` 445) + CSS 1,855 + HTML 504. 이미지 206장 43MB. 빌드 없음, 프레임워크 없음.
- **테스트 자산**: 로직 133항목(단정 427) · 매크로 오탐 · 진행 속도 시뮬 · 브라우저 124항목(Playwright). 이 중 브라우저 스위트는 PNG 개편 이후 낡았다(§3).
- **문서 자산**: CLAUDE.md 의 "반드시 지킬 것" 16개(사고 이력), 에이전트 6종, 기능정의서(주방·쿠폰만), 테스트정의서, features.html(전체지만 8월 31일 이후 추가된 룰렛·출석부·별사탕 상점·우편·공지·절전·도감 컬렉션 누락).

### 1.2 게임 자체

- **콘텐츠 밀도가 높다**: 핵심 루프(조리·설비·업그레이드·환생·명성상점) 위에 일일 루프 7종(출석부·퀘스트·트럭·특선·룰렛·광고·우편) + 이벤트 3종(황금손님·도둑·파티) + 수집 2축(주방 도감·파티 도감) + 경쟁 연출 2종(전국 랭킹·스타 셰프)이 있다. **기능은 충분하다 — 지금 필요한 것은 추가가 아니라 정리·검증·재구성**이다.
- **규칙은 검증됐지만 구조는 서버에 못 올린다**: 전역 세이브 하나, `Date.now()`/`Math.random()` 직접 호출, 클로저 도전과제, 클라가 보상 결정. v2 README 가 정확히 이 이유로 재작성을 결정했다(아키텍처 문서 §1).
- **화면은 기능이 자라며 붙은 상태**: 모달 요소 11개(논리 화면 약 20종, ask·text 모달 재사용)가 같은 박스, HUD 에 칩 5개 + 아이콘 4개(최근 겹침 버그), 탭 6개(에이전트 규칙은 5개). 디자인 시스템 없이 CSS 변수만 있다.
- **그림은 두 세계**: 손그림 PNG 147장 vs 이모지 폴백(도전과제 37 · HUD 아이콘 4 등). `art-prompts.md` 가 66장 명세를 이미 작성.

## 2. 무엇을 어떤 순서로 — 4트랙 병행

```
주차   1              2              3              4              5~8
문서   기능정의서·화면정의서 확정 ──▶ 기획 동결(2주 변경 없음이 조건)
검증   결함 수정 → 브라우저 스위트 갱신 ─────────────▶ 회귀 테스트로 유지
아트   Scenario 학습(1주) ──▶ 66장 생성 ──▶ HUD 아이콘·사장 캐릭터
화면   Figma 라이브러리 ──▶ P0 화면 ──▶ Make 플로우 프로토 ──▶ 지인 테스트 ──▶ P1·P2
코드   config·sim 이식(서버·디자인 불필요, 지금 시작 가능) ──▶ api ──▶ client(Svelte) ──▶ mobile
```

### 트랙 A — 문서 (이번 주)

1. `기능정의서-전체.md` 를 팀이 읽고 **"이 기능은 v2 에 안 간다"** 를 결정한다. 후보: 테스트 도구(디버그 버튼), 가상 랭킹 연출(실랭킹으로 대체), 절전 모드(네이티브에선 OS 담당), 세이브 내보내기 코드(서버 계정으로 대체).
2. 결정된 목록을 아키텍처 문서 §2.2 **액션 카탈로그**에 반영한다. 이것이 서버 API 의 계약이 된다.
3. `features.html` 은 폐기하거나 전체판에서 생성하도록 한다(둘을 따로 유지하면 다시 어긋난다).

### 트랙 B — 검증 (이번 주 → 상시)

1. `검증보고서.md` 의 결함을 심각도 순으로 수정한다(main 에서 — 지인 빌드가 이것이므로).
2. 브라우저 스위트를 갱신한다: SVG → `<img>` 셀렉터, 1회성 모달 닫기 단계, 사람형 입력(좌표·간격 흔들기), 알림 권한 환경 처리. 목표는 **0 실패**로 되돌려 회귀 기준을 회복하는 것.
3. `tests/logic.js` 의 단정은 v2 `sim` Vitest 로 그대로 이식할 자산이다 — 건드릴 때 "왜 이 값인가" 주석을 보강한다.

### 트랙 C — 아트 (Scenario, 1~2주)

디자인 파이프라인 문서 §1 그대로. 핵심은 **기존 147장으로 스타일 모델을 학습**해 66장을 같은 손으로 뽑는 것. 코드 변경은 `data.js` 의 도전과제 `icon` 을 이모지 → 경로로 바꾸는 한 곳.

### 트랙 D — 화면 (Figma Design → Make, 2~4주)

디자인 파이프라인 문서 §2~§3. **순서 고정**: 토큰·컴포넌트 라이브러리 → 정적 화면(상태 변형 포함) → Make 프로토타입 → figma.site 지인 테스트 → 확정. Make 부터 시작하면 범용 스타일로 굳는다.

### 트랙 E — 코드 (v2, 병행)

아키텍처 문서 §7. **단계 1~5(config·sim·migrate)는 디자인·서버 없이 지금 시작 가능**하며 `tests/logic.js` 이식이 완료 기준이다. 서버(6~7)와 클라(8)는 각각 기획 동결·디자인 확정을 기다린다.

| — 설계 확인 | 2건 (환생 시 `taps` 미초기화, 황금손님·도둑 접근성) |
| 서버 분리 위험 | 8범주 — 시계 둘 · 비시드 난수 · 값을 넘기는 API · 저장 안 되는 모듈 상태 · getter 에 쓰기 · UI 직접 mutate · 수치 표현 · 세이브 무결성. 전부 아키텍처 문서에 대응 절이 있음 |

**결론**: 규칙(수치·로직)은 건강하다. 결함은 **시간·저장 경계**(lastSeen, 날짜 역행, 시즌 롤)와 **입력 검증**에 몰려 있고, 이것이 곧 v2 가 서버 권위·시간 주입·Zod 스키마로 가야 하는 이유와 일치한다.
